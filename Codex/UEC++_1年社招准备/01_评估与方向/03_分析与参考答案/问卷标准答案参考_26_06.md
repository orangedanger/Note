# 问卷标准答案参考：2026-06

## 使用说明
- 这不是唯一正确答案，而是面向 `2027-01` UE C++ 游戏客户端社招投递的参考口径。
- 你可以用它对照自己的答卷，判断哪些分数需要校准，哪些证据需要补充。
- 如果你达不到参考答案，不代表不能投递；它只是告诉你接下来该补什么。
- 评分时优先看“证据”，不要只看“我觉得我会”。

## 一、个人能力自测参考答案

### 总体评分口径
- `4` 分：做过项目级实践，能讲清设计、坑、调试、取舍和验证。
- `3` 分：能独立实现基础版本，能解释流程和常见问题。
- `2` 分：跟着资料能做出来，离开资料会卡。
- `1` 分：看过概念或教程，没有独立做过。
- `0` 分：基本没接触。

### F. 三个候选方向参考答案

#### 候选 1：小型 ARPG 战斗训练场
- 一句话描述：玩家在一个小型训练场中使用普通攻击和 2 个技能击败敌人，后续加入双人同步。
- 核心玩法：移动、攻击、技能、冷却、Buff/状态、敌人追击攻击、血量 HUD。
- 展示的 C++ 能力：Gameplay 组件化、属性系统、技能数据配置、AI 状态、UMG 通信、第二阶段网络复制。
- 最大风险：动画、AI 和联机同步叠加后范围膨胀。
- 第一版必须有：一个玩家、一个敌人、2 个技能、血条、冷却、胜负流程。

#### 候选 2：小型联机射击生存 Demo
- 一句话描述：1-2 名玩家在小场景中击败敌人波次，展示武器、血量和网络同步。
- 核心玩法：射击、换弹/冷却、敌人波次、血量同步、击杀结算。
- 展示的 C++ 能力：RPC、属性复制、命中检测、敌人 AI、基础 HUD。
- 最大风险：射击手感和网络调试会占用较多时间。
- 第一版必须有：移动、射击、一个敌人、血量同步、双客户端测试。

#### 候选 3：Roguelike 房间战斗 Demo
- 一句话描述：玩家清理一个小房间，获得随机技能或 Buff，进入下一波战斗。
- 核心玩法：房间战斗、掉落、技能升级、敌人波次。
- 展示的 C++ 能力：数据驱动、掉落系统、Buff、UI、敌人生成。
- 最大风险：系统数量多，容易做成半成品。
- 第一版必须有：一个房间、两波敌人、一个随机 Buff、结算 UI。

## 三、对照你当前答卷的校准建议

### 你可以保留的判断
- 战斗、技能、AI 作为核心方向是对的。
- 联机作为加分项是对的。
- 不做剧情演出是对的。
- 使用免费资源、灰盒优先、单关卡闭环是更合理的路线。

### 你需要校准的地方
- C++ 部分不要因为“做过项目会用”就给 `4`；能讲清机制和坑才适合 `4`。
- UE 核心机制里，反射、CDO、GC、生命周期这些要先补，不然面试会被追问穿。
- 网络部分你有实践，但 Ownership、`stat net`、复制条件、相关性还需要补。
- UI 和动画兴趣低没问题，但战斗 Demo 的最小 HUD 和基础动画不能完全不做。
- 简历和项目讲述必须提前准备，不能完全依赖 AI 生成。
