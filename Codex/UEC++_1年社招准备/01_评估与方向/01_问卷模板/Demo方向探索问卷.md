# UE C++ 游戏客户端 Demo 方向探索问卷

## 使用方式
- 建议填写时间：30-45 分钟，可以分两次填。
- 目标不是立刻想出“大作”，而是找到一个能在 `2026-09` 前做出第一版、`2026-12` 前打磨成作品集的 Demo。
- 每个问题尽量写真实偏好，不要只写“面试看起来厉害”。
- 不需要精确判断自己“到底几分”，只要选择最像你当前状态的描述。
- 如果两个分数都像，先选低一档；后面可以根据实际开发进展调高。

## Demo 选择原则
- 小而完整：宁愿 1 个玩法闭环讲深，也不要 5 个半成品系统。
- C++ 含量明确：核心系统必须由 C++ 实现，蓝图负责配置和表现。
- 可演示：5 分钟内能让面试官看懂你做了什么。
- 可深挖：每个系统都能讲设计、坑、调试和取舍。
- 可完成：在职备战下，必须控制范围。

## 不知道怎么评分时先看这里

### 兴趣分
- `0`：完全不想做，哪怕它对面试有用也不想碰。
- `1`：不排斥，但做不做都行。
- `2`：愿意做一个基础版本。
- `3`：比较想做，愿意投入几周时间打磨。
- `4`：非常想做，如果 Demo 没有它，会觉得不像自己想做的东西。

### 把握分
- `0`：没接触过，也不知道从哪里开始。
- `1`：看过视频或文章，但没有自己动手做出来。
- `2`：跟着教程能做出基础效果，离开教程会卡。
- `3`：能独立做出基础版本，能解释主要流程和常见坑。
- `4`：做过项目级实践，能讲清设计、问题定位、取舍和优化。

### 备注怎么写
- 写“为什么想做”：例如“我喜欢近战打击感”“我想展示 C++ 组件化”。
- 写“证据”：例如“做过一个蓝图版交互门”“只看过 RPC 教程，没有独立做过”。
- 写“担心点”：例如“动画资源不够”“网络同步怕调不出来”“UI 做得慢”。
- 如果真的不知道，就写“不确定”，不要空着。

### B 模块判断
- 高兴趣 + 高把握：适合做 Demo 核心。
- 高兴趣 + 低把握：适合做挑战点，但第一版要简化。
- 低兴趣 + 高把握：适合当辅助功能，不要占太多时间。
- 低兴趣 + 低把握：优先砍掉。

## 可选参考方向

### 方向 1：第三人称动作交互 Demo
- 核心：移动、锁定、轻重攻击、闪避、交互物、HUD。
- 适合展示：3C、战斗、Enhanced Input、ActorComponent、UI、数据驱动。
- 风险：动画和手感容易耗时间。

### 方向 2：Roguelike 房间战斗 Demo
- 核心：房间生成、敌人波次、掉落、技能升级、结算 UI。
- 适合展示：Gameplay 系统、数据配置、UI、简单 AI、存档。
- 风险：系统多，必须砍美术和关卡复杂度。

### 方向 3：双人联机互动 Demo
- 核心：创建/加入、角色同步、交互同步、简单战斗或合作机关。
- 适合展示：RPC、Replication、服务器权威、网络调试。
- 风险：网络坑多，不建议作为第一版唯一核心，除非已有基础。

### 方向 4：解谜机关探索 Demo
- 核心：角色移动、交互、机关状态、门、钥匙、提示 UI、存档。
- 适合展示：组件化交互、数据驱动、状态管理、UI、关卡流程。
- 风险：玩法表现可能不如战斗直观，需要文档讲清技术点。
