## P0：UE C++ 必学资料

### 1. `UObject`、反射、UHT、宏
- 官方文档：
  - https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine
  - https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties
  - https://dev.epicgames.com/documentation/unreal-engine/ufunctions-in-unreal-engine
- 本地源码入口：
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\Object.h`
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\ObjectMacros.h`
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\Class.h`
- 必须掌握：
  - `UObject` 不是普通 C++ 对象，它接入了反射、序列化、GC 等系统。
  - `UCLASS`、`UPROPERTY`、`UFUNCTION` 会被 UHT 解析，生成反射元数据。
  - `.generated.h` 必须放在头文件最后 include。
  - `GENERATED_BODY()` 是 UE 生成反射胶水代码的入口。
- 一句话面试回答：
  - UE 通过 UHT 在编译前扫描带宏的头文件，生成反射元数据，让 C++ 类型能被编辑器、蓝图、序列化、GC 和网络复制系统识别。

### 2. CDO 和对象创建
- 官方文档：
  - https://dev.epicgames.com/documentation/unreal-engine/creating-objects-in-unreal-engine
- 本地源码入口：
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\UObjectGlobals.h`
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\Class.h`
- 必须掌握：
  - CDO 是 Class Default Object，保存类的默认属性。
  - 构造函数会用于构建 CDO，也可能在编辑器阶段执行。
  - 构造函数适合 `CreateDefaultSubobject` 和默认值设置。
  - 运行时逻辑、依赖 `World`、依赖玩家输入、访问其他运行时 Actor 的逻辑不应放在构造函数。
  - `CreateDefaultSubobject` 用于构造函数中创建默认子对象。
  - `NewObject` 用于运行时创建非 Actor 的 `UObject`。
  - `SpawnActor` 用于运行时生成 Actor。
- 一句话面试回答：
  - CDO 是 UE 每个 `UClass` 的默认对象，新实例会基于它的默认属性初始化，所以构造函数应该只做默认子对象和默认值配置，不应该写依赖运行时世界状态的 Gameplay 逻辑。

### 3. GC、`UPROPERTY`、指针类型
- 官方文档：
  - https://dev.epicgames.com/documentation/unreal-engine/unreal-object-handling-in-unreal-engine
- 本地源码入口：
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\Object.h`
  - `D:\soft\UE_5.7\Engine\Source\Runtime\CoreUObject\Public\UObject\ObjectPtr.h`
- 必须掌握：
  - UE GC 追踪 `UObject` 引用链。
  - 成员 `UObject` 引用需要用 `UPROPERTY()` 标记，UE5 推荐 `TObjectPtr<T>`。
  - 裸 `UObject*` 可以用于局部变量和参数，但不适合长期保存为成员引用。
  - `TWeakObjectPtr` 适合非拥有引用，对象销毁后可安全判断。
  - `TSharedPtr`/`TUniquePtr` 适合非 `UObject` 的普通 C++ 对象，不要管理 `UObject`。
- 一句话面试回答：
  - UE 的 GC 只能追踪它知道的 `UObject` 引用，成员变量如果没有 `UPROPERTY`，GC 可能无法识别这条引用，导致对象被回收后留下悬垂指针。

### 4. Actor/Component 生命周期
- 官方文档：
  - https://dev.epicgames.com/documentation/unreal-engine/actors-in-unreal-engine
  - https://dev.epicgames.com/documentation/unreal-engine/components-in-unreal-engine
- 本地源码入口：
  - `D:\soft\UE_5.7\Engine\Source\Runtime\Engine\Classes\GameFramework\Actor.h`
  - `D:\soft\UE_5.7\Engine\Source\Runtime\Engine\Classes\Components\ActorComponent.h`
- 必须掌握：
  - Actor 构造函数用于默认组件和值。
  - Component 需要注册后才参与世界。
  - `BeginPlay` 是运行时 Gameplay 初始化的常用入口。
  - Tick 需要开启，且不要滥用。
  - `EndPlay` 可能因为销毁、关卡切换、PIE 停止等原因触发。
- 一句话面试回答：
  - 我通常在构造函数创建默认组件和设置默认值，在 `BeginPlay` 做依赖运行时世界的初始化，在 `EndPlay` 解绑委托、清理 Timer 或释放运行时引用。

## P0：C++ 必学资料

### 1. RAII 和智能指针
- 参考资料：
  - https://en.cppreference.com/w/cpp/language/raii
  - https://en.cppreference.com/w/cpp/memory/unique_ptr
  - https://en.cppreference.com/w/cpp/memory/shared_ptr
  - https://en.cppreference.com/w/cpp/memory/weak_ptr
- 必须掌握：
  - RAII 是用对象生命周期管理资源。
  - `unique_ptr` 表示独占所有权。
  - `shared_ptr` 表示共享所有权，但可能出现循环引用。
  - `weak_ptr` 用于观察 `shared_ptr` 管理对象，解决循环引用。
  - UE 中 `UObject` 不用 `shared_ptr` 管理，普通 C++ 对象才用。
- 一句话面试回答：
  - RAII 的核心是资源在构造时获取、析构时释放，从而把资源释放绑定到对象生命周期，减少手动释放导致的泄漏和异常路径问题。

### 2. 拷贝/移动语义
- 参考资料：
  - https://en.cppreference.com/w/cpp/language/copy_constructor
  - https://en.cppreference.com/w/cpp/language/move_constructor
  - https://en.cppreference.com/w/cpp/language/rule_of_three
- 必须掌握：
  - 拷贝构造复制资源。
  - 移动构造转移资源所有权。
  - Rule of 3/5/0。
  - 移动后的对象仍有效，但状态通常不应依赖。
- 一句话面试回答：
  - 移动语义用于把临时对象或即将不用的对象资源转移出去，减少深拷贝成本，常见于容器扩容、返回值和资源管理类。

### 3. 对象切片、虚析构、接口类
- 参考资料：
  - https://en.cppreference.com/w/cpp/language/virtual
  - https://en.cppreference.com/w/cpp/language/abstract_class
- 必须掌握：
  - 基类按值接收子类会发生对象切片。
  - 有虚函数的基类通常应有虚析构。
  - 纯虚类可以作为接口。
  - UE 中接口还会涉及 `UINTERFACE` 和 `IInterface` 两部分。
- 一句话面试回答：
  - 对象切片是把派生类对象按值赋给基类对象时，派生类特有部分被丢掉；如果要保留多态，应通过指针或引用传递。

## P1：本周了解即可

### Subsystem
- 本地源码和参考：
  - `UGameInstanceSubsystem`
  - `UWorldSubsystem`
  - `ULocalPlayerSubsystem`
- 需要知道：
  - Subsystem 是 UE 管理生命周期的单例式系统。
  - `GameInstanceSubsystem` 跨关卡存在。
  - `WorldSubsystem` 随 World 存在。
  - `LocalPlayerSubsystem` 按本地玩家存在。

### 软引用和异步加载
- 需要知道：
  - 硬引用会把资源拉进加载链。
  - 软引用适合延迟加载资源。
  - 后续 Demo 的技能图标、怪物资源、特效资源可以考虑软引用。
