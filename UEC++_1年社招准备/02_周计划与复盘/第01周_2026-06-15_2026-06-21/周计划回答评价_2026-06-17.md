### 1. `FVector` 是不是 `UObject`？为什么仍然能在 UE 中使用？

你的回答：
> 不是，我看到 using FVector TVector 然后看TVector是个struct，至于为什么能使用可能他在上面头文件就被加入了依赖关系

### 评分
- 当前：`3/4`
- 理由：判断 `FVector` 不是 `UObject` 是对的，而且你已经开始查源码确认 `TVector` 是 `struct`。但“因为头文件依赖”只解释了 C++ 编译能看到类型，没有解释 UE 为什么大量使用非 UObject 值类型。

### 源码证据
- `D:\soft\UE_5.7\Engine\Source\Runtime\Core\Public\Math\MathFwd.h`
  - `FVector` 在 UE 5.7 中是 `using FVector = UE::Math::TVector<double>`。
- `D:\soft\UE_5.7\Engine\Source\Runtime\Core\Public\Math\Vector.h`
  - `TVector` 是普通 C++ `struct`，不是 `UObject`。

### 需要修正

### 更好的面试表达

## 9. 为什么 `.generated.h` 不能手动修改？UHT 错误和 C++ 编译错误有什么区别？

- 理由：第一问答对了，第二问还没建立区分。

### 需要补充
- `.generated.h` 是 UHT 在 C++ 编译前根据反射宏生成的中间代码，下一次生成会覆盖你的手改。
- UHT 错误通常发生在 C++ 编译前，常见原因是反射宏、specifier、类型暴露、`.generated.h` include 顺序、`GENERATED_BODY()` 缺失。

### 更好的面试表达

### 具体例子：释放技能造成伤害
假设玩家按下技能键，流程可以这样拆：

1. `APlayerCharacter` 或输入层收到输入，调用 `SkillComponent->TryActivateSkill(SkillId)`。
2. `SkillComponent` 检查冷却、消耗、技能配置，然后广播 `OnSkillCommit` 或返回一个 `FSkillRequest`。
3. `CombatComponent` 监听或接收这个请求，负责命中检测、攻击窗口、伤害结算。
4. `HealthComponent` 只接收最终伤害请求并修改血量，然后广播 `OnHealthChanged`。
5. UI 只订阅血量/技能冷却事件，不反向控制核心 Gameplay 组件。

这个设计里，Skill 管技能规则，Combat 管战斗结算，Health 管生命值，UI 管显示，Character/Owner 负责把组件装配起来。

### 更好的面试表达
我会先判断二者职责关系。如果 Skill 是 Combat 流程的一部分，可以让 Character 或 Combat 作为协调者，Skill 只负责技能数据、冷却和释放请求，Combat 负责命中和伤害结算；二者通过接口或委托通信。如果 Skill 和 Combat 更独立，我也会优先用 Owner 作为组合根来装配，而不是一上来做全局单例。组件之间可以缓存同 Owner 上的组件引用，但要保持依赖方向清晰，避免互相知道太多内部细节。
