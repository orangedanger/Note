# 周计划：2026-07-06 至 2026-07-12（装机后重排版）

## 调整说明
- `2026-07-06` 至 `2026-07-09` 主要用于安装和配置电脑，Demo 项目尚未推进。
- 当前只剩周五晚和周末，不补偿式赶工，也不把原定 4 天的 GAS 开发压缩到 2 天。
- 第 04 周改为“开发环境恢复 + 项目基线确认周”。
- 原计划中的 GAS 最小闭环整体顺延到第 05 周；本周最多只做依赖检查，不进入大规模接入。

## 本周唯一主目标
在新电脑上恢复 UE C++ 开发环境，并确认 `TPRPG` 工程可以编译、打开、运行，且第 03 周已有攻击闭环仍可复现。

## 时间预算
- 周五：`60-90` 分钟，完成环境清点和工程首次启动。
- 周六：`3-4` 小时，解决编译或资源问题，恢复旧战斗闭环。
- 周日：`2-3` 小时，复验、记录问题并准备第 05 周 GAS 接入。
- 如果环境问题超时，优先保证工程可运行，取消所有新增功能。

## P0 必须完成
- 确认 UE、Visual Studio、Windows SDK、Git/LFS 等项目依赖可用。
- 确认引擎版本和项目关联正确；如果新电脑路径变化，记录新路径。
- `TPRPG` 能生成项目文件并完成一次 Development Editor 编译。
- 编辑器能打开目标地图并进入 PIE。
- 验证第 03 周旧闭环：
  - 玩家可以移动。
  - Attack 输入可以触发。
  - `gp.Combat.DrawAttackDebug 1` 能显示 Sweep。
  - 木桩可以被命中、扣血和死亡。
- 记录仍存在的问题和第 05 周开始 GAS 前的阻塞项。

## P1 有余力再做
- 检查 `.uproject` 中 `GameplayAbilities` 插件是否启用。
- 检查 `GPGameplay.Build.cs` 当前依赖，列出需要新增的：
  - `GameplayAbilities`
  - `GameplayTags`
  - `GameplayTasks`
- 如果旧闭环完全稳定，可只提交 GAS 模块依赖修改并验证编译。
- 不新建 ASC、AttributeSet、Ability 或 GameplayEffect 类。

## 本周明确不做
- 不在周末强行完成 GAS 最小闭环。
- 不做 `UGA_BasicAttack`、`UGE_Damage`、Fireball、冷却或 UI。
- 不做联机复制、预测、GameplayCue 或复杂 AbilityTask。
- 不为了追回进度熬夜；环境恢复耗时超过预算时，功能开发全部顺延。

  - 确认 Visual Studio 的“使用 C++ 的游戏开发”、MSVC、Windows SDK 已安装。

## 第 05 周承接顺序
仅在第 04 周 P0 全部通过后按以下顺序推进：

1. 加入 GAS 模块依赖，创建 ASC 和 `UGPHealthAttributeSet`。
2. 让 `AGPCharacter` 实现 `IAbilitySystemInterface`，完成属性初始化。
3. 创建 `UGPGameplayAbility` 和 `UGA_BasicAttack`，让输入激活 Ability。
4. 接入 `UGE_Damage`，让普通攻击通过 GAS 修改目标 Health。
5. 整理旧 `UGPAttributeSetComponent` 到 GAS AttributeSet 的迁移边界。

Fireball、UI、冷却与联机内容继续保持 P1/P2，不进入第 05 周 P0。
