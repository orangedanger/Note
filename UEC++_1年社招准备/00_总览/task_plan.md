## 准备主线

### 1. C++ 基础与工程能力
- 状态：`pending`
- 目标：面试中能稳定解释和手写 C++，项目中能写出可维护、可调试、性能意识明确的代码。
- 重点：
  - C++ 对象模型、构造/析构、拷贝/移动语义、RAII、智能指针。
  - STL 容器、迭代器失效、哈希表、排序、内存布局、缓存友好性。
  - 多态、模板、类型擦除、lambda、线程同步、原子操作基础。
  - 数据结构与算法：数组、链表、栈队列、树、图、堆、哈希、排序、二分、DFS/BFS、动态规划入门。
  - 工程实践：Git、调试器、日志、断点、崩溃调用栈、代码规范、单元测试意识。
- 交付物：
  - `C++_复习清单.md`：整理 80-120 个高频问题。
  - `算法_每周记录.md`：每周 8-12 题，优先中等题，记录错因。
  - 一个纯 C++ 小项目：如 ECS 原型、事件系统、对象池、资源句柄管理器、状态机框架。

### 2. Unreal C++ 核心机制
- 状态：`pending`
- 目标：从“会调用 API”提升到“理解 UE 为什么这样设计”。
- 重点：
  - `UObject`、`UCLASS`、`UPROPERTY`、`UFUNCTION`、反射、序列化、GC、CDO。
  - `Actor` / `ActorComponent` 生命周期：构造函数、`PostInitializeComponents`、`BeginPlay`、`Tick`、`EndPlay`、销毁。
  - 模块系统、`Build.cs`、插件结构、头文件依赖、前向声明、热重载限制。
  - 资源引用：硬引用、软引用、异步加载、Asset Manager、DataAsset、DataTable。
  - 委托、事件、Timer、Subsystem、Gameplay Tags、SaveGame。
- 交付物：
  - `UE核心机制_源码阅读笔记.md`：每个机制配一个源码入口、一个最小例子、一个面试表达。
  - 一个 UE C++ 插件或模块：包含可配置数据、运行时系统、Editor 辅助工具之一。

### 3. Gameplay 客户端能力
- 状态：`pending`
- 目标：能独立实现角色、交互、战斗、任务、背包、UI 等常见客户端功能。
- 重点：
  - Gameplay Framework：`GameInstance`、`GameMode`、`GameState`、`PlayerState`、`PlayerController`、`Pawn`、`Character`。
  - Enhanced Input：`InputAction`、`InputMappingContext`、Trigger、Modifier、运行时切换输入上下文。
  - 角色移动：`CharacterMovementComponent`、移动模式、Root Motion、简单预测问题。
  - 交互系统：射线检测、碰撞通道、接口、组件化、交互提示 UI。
  - 战斗系统：技能、Buff、属性、伤害结算、冷却、命中检测、表现与逻辑分离。
  - UI：UMG、Widget 生命周期、数据绑定策略、MVVM 基础、UI 与 Gameplay 通信。
- 交付物：
  - 一个 3C 原型：Character、Camera、Control 手感完整。
  - 一个可展示玩法 Demo：至少包含移动、交互、战斗、UI、存档或关卡流程。
  - `Gameplay_系统设计复盘.md`：说明每个系统的职责划分、数据流、扩展点、踩坑。

### 4. 网络同步与多人基础
- 状态：`pending`
- 目标：达到客户端社招常见“懂同步、会排查、能按服务器权威思路写逻辑”的水平。
- 重点：
  - Client-Server 架构、Authority、Ownership、Role、RPC、属性复制、`RepNotify`。
  - `GameState` / `PlayerState` / `PlayerController` / `Pawn` 在多人中的职责。
  - Actor 复制开销、相关性、优先级、Dormancy、网络带宽意识。
  - 常见问题：客户端直接改权威状态、RPC 调用对象无 Owner、UI 读错端、延迟下表现不一致。
- 交付物：
  - 一个双人联机小 Demo：房间/加入、移动同步、交互同步、简单战斗同步。
  - `网络同步_问题清单.md`：记录 30 个典型坑和排查方式。

### 5. 性能、调试与问题定位
- 状态：`pending`
- 目标：面试和工作中能说明“如何发现问题、定位瓶颈、验证优化结果”。
- 重点：
  - `stat unit`、`stat game`、`stat slate`、`stat net`、Unreal Insights。
  - Tick 管理、对象创建销毁、容器分配、GC 压力、资源加载卡顿。
  - Draw Call、材质复杂度、LOD、动画开销、UI 刷新开销。
  - 日志分类、断言、Crash dump、调用栈、复现步骤、最小化问题。
- 交付物：
  - `性能优化案例集.md`：至少 5 个真实或自造问题，每个包含现象、数据、原因、修改、结果。
  - Demo 中加入可开关的 Debug UI 或 Console 命令。

### 6. 引擎源码阅读
- 状态：`pending`
- 目标：能围绕岗位相关模块读源码，而不是无边界地啃引擎。
- 推荐顺序：
  - `UObject` / GC / 反射相关。
  - `Actor` 生命周期与 Component 注册。
  - Gameplay Framework 关键类。
  - Enhanced Input。
  - Replication / RPC。
  - UMG / Slate 基础。
  - Asset loading / Package。
- 方法：
  - 每次只读一个问题，例如“`BeginPlay` 是从哪里被调用的？”。
  - 记录调用链，不追求一次读完所有分支。
  - 每篇笔记必须有“面试怎么讲”和“项目中怎么用”。
